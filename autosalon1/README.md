# Автосалон — лабораторна - 4: авторизація та захищені точки доступу (Node.js)

Проєкт продовжує лабораторну роботу «Автосалон» (марки машин, комплектації,
клієнти, продажі, додаткові опції) і додає авторизацію користувачів через
**Passport.js** з розділенням прав доступу за ролями.

## Запуск

```bash
npm install
npm start
```

Додаток: http://localhost:3000

## Тестові акаунти

| Логін | Пароль | Роль |
|---|---|---|
| admin | admin123 | Адміністратор |
| manager | manager123 | Менеджер |
| visitor | visitor123 | Відвідувач |

Також можна зареєструватися самостійно — нові користувачі завжди отримують
роль «відвідувач».

## Ролі та права доступу

| Дія | Відвідувач (visitor) | Менеджер (manager) | Адміністратор (admin) |
|---|---|---|---|
| Перегляд списків і головної | так | так | так |
| Додавання / редагування / видалення записів автосалону | ні (403) | так | так |
| Керування користувачами (`/users`) | ні (403) | ні (403) | так |

Незалогіненому користувачу (гість) доступні лише сторінки входу,
реєстрації та перегляд списків; усі дії редагування перенаправляють на `/login`.

## Що додано у цій частині

- `auth.js` — налаштування Passport.js (локальна стратегія), серіалізація
  сесії, middleware `requireRole(...)` для захисту точок доступу
- Сесії через `express-session`
- Паролі зберігаються у вигляді bcrypt-хешів (`bcryptjs`)
- Сторінки входу, реєстрації (з серверною валідацією) і виходу
- Сторінка керування користувачами для адміністратора:
  створення, зміна ролі/даних, видалення (головного адміністратора №1
  та останнього адміністратора видалити не можна)
- Кнопки редагування приховуються у інтерфейсі для відвідувача
  (але захист виконано і на сервері — прямий POST повертає 403)

## Структура проєкту

| Файл | Призначення |
|---|---|
| `server.js` | Express-сервер: сесії, Passport, усі маршрути, серверна валідація |
| `auth.js` | Стратегія Passport, middleware захисту за ролями |
| `entities.js` | Опис сутностей: поля, типи, валідатори, правила видалення |
| `validators.js` | Бібліотека валідаторів (обов'язковість, довжина, число, email, телефон, дата, унікальність, зовнішній ключ) |
| `views.js` | HTML-шаблони (списки, форми, вхід/реєстрація, користувачі) |
| `db.js` | Файлове JSON-сховище (`data/db.json`, створюється автоматично) |

## Серверна валідація

У HTML-формах **немає жодного атрибута `required`** — усі перевірки
виконуються на сервері (як для даних автосалону, так і для реєстрації
та керування користувачами). При помилках форма повертається з введеними
значеннями та повідомленнями українською під кожним полем (HTTP 400).

Правила для даних автосалону — як у частині 1 (див. README першого проєкту).
Для користувачів: логін 3–20 символів (латиниця, цифри, `_`), унікальний;
ПІБ 5–60 симв.; роль з списку; пароль від 6 символів (при редагуванні
можна залишити порожнім — тоді не змінюється); при реєстрації — пароль
підтверджується двічі.
Railway сам виконує `npm install` і `npm start`; порт читається зі змінної `PORT`.
Тестові акаунти (admin/admin123, manager/manager123, visitor/visitor123) вже є у файловій базі.

**Збереження даних.** Записи зберігаються у `data/db.json` усередині контейнера.
Щоб дані не зникали після передеплою: **Settings -> Volumes** (mount path `/data`)
та змінна `DATA_DIR=/data` у **Variables**.
